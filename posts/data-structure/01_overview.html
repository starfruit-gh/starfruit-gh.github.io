（一）概述

数据结构的基本概念与术语

数据、数据元素、数据项和数据对象

  • 数据（Data）：是所有能输入计算机并能被计算机程序处理的符号的总称。包括：数字、字符串、表、图、音频、视频...
  • 数据元素（Data Element）：是数据的基本单位。简称元素，或称为记录、结点、顶点。
  • 数据项（Data Item）：是组成数据元素的、有独立含义的、不可分割的最小单位。
  • 数据对象（Data Object）：是性质相同的数据元素的集合。例如：整数集N={0,±1,±2,...}、字母字符集C={'A','B','C'...'a','b','c',...}。

数据结构

定义

数据结构（Data Structure）：是相互之间存在一种或多种特定关系的数据元素的集合。DS={“数据元素”+“结构(关系)”}。

三要素

逻辑结构
  • 集合结构：数据元素之间除了属于同一集合的关系外，别无其他关系。
  • 线性结构：数据元素之间存在着一对一的关系。
  • 树结构：数据元素之间存在着一对多的关系。
  • 图结构(网结构)：数据元素之间存在着多对多的关系。
存储结构
  • 顺序存储结构：将逻辑上相邻的数据元素依次存储在地址连续的存储单元中。数据元素的逻辑顺序与其存储顺序一致，因此可以实现随机存取。
  • 链式存储结构：将数据元素存储在地址任意的存储单元中。每个数据元素不仅包含数据本身（数据域），还包含一个或多个指针（指针域），通过这些指针来指示其前驱和/或后继元素的位置，从而表示元素间的逻辑关系。
  • 索引存储结构：在存储数据元素（主数据区）的同时，还额外建立附加的索引结构（最常见的是索引表）。索引表中的每项称为索引项，通常包含能唯一标识数据元素的关键字和对应数据元素在主数据区的存储地址。而索引表是按关键字有序排列的，因此可以通过索引项快速找到元素的存储地址，进而定位到数据本身。
  • 散列存储结构：又称哈希（Hash）存储结构，核心是通过哈希函数（关键字到存储地址的映射函数），根据数据元素的关键字直接计算出该元素的存储地址，实现数据的快速定位。
运算和实现
  • 运算（针对逻辑结构）：对数据元素可以施加的操作。
  • 实现（针对存储结构）：可施加的操作在相应的存储结构上的实现。

数据类型

数据类型（Data Type）：是一个值的集合和定义在这个集合上的一组操作的总称。

数据在存储时所需要的存储空间各不相同，所以不同的数据在存储时要分配不同大小的存储空间，因此要用不同的数据类型来区分。

数据类型定义了数据的性质、取值范围、存储方式以及对数据所能进行的运算和操作。

抽象数据类型

抽象数据类型（Abstract Data Type，ADT）：一般指由用户定义的一个数学模型以及定义在这个模型上的一组操作的总称，包括三个部分：数据对象、数据关系、基本操作。

算法

算法的定义

算法（Algorithm）：是解决特定问题求解步骤的描述，在计算机中表现为指令的有限序列，且每条指令表示一个或多个操作。

算法的特性

  • 有穷性：一个算法必须在执行有穷步骤后结束，而且每一步必须在有穷时间内完成。
  • 确定性：算法中的每条指令必须有确切的含义，每一步操作都没有二义性，对于相同的输入只能得出相同的输出。
  • 可行性：算法不能是空中楼阁，算法中的所有操作都必须可以通过 已经实现的基本操作 运算执行有限次来实现。
  • 输入：一个算法可以有零个或多个输入。
  • 输出：一个算法至少有一个或多个输出。

算法的设计要求

  • 正确性：算法的正确性并非仅仅指语法正确或通过部分测试用例，而是指对于问题定义范围内的所有合法输入，算法都能够在有限时间内产生符合预期的正确结果。
  • 可读性：算法应当具有良好的结构、清晰的逻辑和恰当的注释，以便于理解、交流，降低协作和维护成本。
  • 健壮性：当算法接收到不符合预设条件（包括边界条件、异常值或非法格式）的输入时，算法能恰当的做出反应或进行处理，而不是产生莫名其妙的输出结果或出现不可预期的副作用或系统级故障。
  • 高效性：算法在执行过程中应高效利用计算资源，要花费尽量少的时间和尽量低的存储。

算法的好坏分析

解决同一个问题，可以有许多不同的算法。那要如何评判不同算法的好坏呢？

一个好的算法首先要具备正确性，然后是健壮性，可读性，在几个方面都满足的情况下，主要考虑算法的效率，通过算法的效率高低来评判不同算法的优劣程度。

算法效率的度量可以从两方面考虑：算法的时间效率和算法的空间效率。

  • 时间效率：指的是算法执行所耗费的时间。
  • 空间效率：指的是算法执行过程中所耗费的存储空间。

算法效率的度量方法有两种：事后统计和事前分析。

  • 事后统计：是一种将算法编程实现，真正运行之后，测算其时间和空间开销的方法。
  • 事前分析：是一种在算法实现和运行之前，通过理论分析，估算其时间和空间开销的方法。

由于事后统计需要先将算法实现为可执行程序，不仅耗费较多时间与精力，且测算结果受计算机软硬件等环境因素影响，因此通常采用事前分析来度量算法的效率。

算法的时间复杂度

算法的执行时间

算法的执行时间 = Σ(每条语句的执行次数×该语句执行一次所需的时间)

  • 每条语句的执行次数：又称语句频度，取决于算法中的控制结构和问题规模。
  • 语句执行一次所需的时间：取决于机器的指令性能、运行速度以及编译的代码质量等，是由机器本身软硬件环境决定的，与算法无关。

此时，看一个算法的执行时间就只看算法所有语句的频度之和即可。

假设问题规模为n，算法所有语句的频度之和用f(n)表示，算法的执行时间用T(n)表示。则有T(n)=f(n)。

举个例子：

// 计算两个n×n矩阵的乘积
func matrixMultiply(a, b [][]int, n int) [][]int {
    result := make([][]int, n)     // 语句1：执行1次
    for i := 0; i < n; i++ {       // 语句2：执行n+1次
        result[i] = make([]int, n) // 语句3：执行n次
    }
    
    for i := 0; i < n; i++ {       // 语句4：执行n+1次
        for j := 0; j < n; j++ {   // 语句5：执行n×(n+1)次
            sum := 0               // 语句6：执行n×n次
            for k := 0; k < n; k++ { // 语句7：执行n×n×(n+1)次
                sum += a[i][k] * b[k][j] // 语句8：执行n×n×n次
            }
            result[i][j] = sum     // 语句9：执行n×n次
        }
    }
    return result                  // 语句10：执行1次
}

// T(n) = f(n) = 3n³ + 4n² + 7n + 6

分析以上数据可以得出：对于不同的算法，当问题规模n比较小的时候，各算法之间的执行时间差距不大，但随着n的增大，各算法的执行时间差距急剧增大，增长快的算法会迅速远超增长慢的算法。这一规律清晰表明：低次项和常数项对算法执行时间的影响，在n足够大时会被逐渐稀释，真正决定算法长期效率的是其时间复杂度的最高次项。最高次项的阶数直接主导了算法执行时间的增长速率，最终成为区分不同算法效率上限的关键因素。

算法的时间复杂度

算法的时间复杂度就是：算法的所有语句频度之和关于问题规模n的函数f(n)的最高次项的数量级（Order），记作O(f(n))。

算法的基本语句频度

既然算法的时间复杂度只和f(n)的最高次项的数量级有关，那就没必要用所有语句频度之和来求解一个算法的时间复杂度了，直接找能影响f(n)最高次项的语句即可，这种语句就是基本语句。

同样的例子：

// 计算两个n×n矩阵的乘积
func matrixMultiply(a, b [][]int, n int) [][]int {
    result := make([][]int, n)
    for i := 0; i < n; i++ {
        result[i] = make([]int, n)
    }
    
    for i := 0; i < n; i++ {
        for j := 0; j < n; j++ {
            sum := 0
            for k := 0; k < n; k++ {
                sum += a[i][k] * b[k][j]  // 基本语句，执行n×n×n次
            }
            result[i][j] = sum
        }
    }
    return result
}

// T(n) = f(n) = n³
// O(n) = n³

算法时间复杂度的计算

方法
  1. 找出语句频度最大的语句作为基本语句
  2. 得出基本语句关于问题规模n的函数f(n)
  3. 用1取代所有加法常数
  4. 前三步得到的结果只保留最高阶项
  5. 前四步后的结果若存在且不为1，则去除其常数系数
规则
  • 加法规则：T(n)=T1(n)+T2(n)=O(f(n))+O(g(n))=O(max(f(n), g(n)))
  • 乘法规则：T(n)=T1(n)×T2(n)=O(f(n))×O(g(n))=O(f(n)×g(n))

Eg：T(n)=n³+n²log₂n=O(n³)+O(n²log₂n)=O(n²n)+O(n²log₂n)=O(n³)

常见的时间复杂度

常用的时间复杂度所耗费的时间从小到大依次是：O(1) < O(logn) < O(n) < O(nlogn) < O(n²) < O(n³) < O(2ⁿ) < O(n!) < O(nⁿ)

像O(n³)、O(2ⁿ)、O(n!) 、O(nⁿ)等这样的时间复杂度，除非n的值很小，否则哪怕n只是100，都是噩梦般的运行时间。所以这种不切实际的算法时间复杂度，一般都不去讨论它。

最好、最坏和平均时间复杂度

  1. 算法在最好情况下的时间复杂度称为最好时间复杂度。
  2. 算法在最坏情况下的时间复杂度称为最坏时间复杂度。
  3. 算法的平均时间复杂度是指：算法在所有可能情况下，按照输入实例以等概率出现时，算法计算量的加权平均值。

除特别指明外，算法时间复杂度一般都是指最坏情况下的时间复杂度。

// 线性查找：在数组中查找目标值
func linearSearch(arr []int, target int) int {
    // 遍历数组
    for i := 0; i < len(arr); i++ {
        // 如果找到目标值，返回索引
        if arr[i] == target {
            return i
        }
    }
    // 未找到目标值，返回-1
    return -1
}

// 最好时间复杂度：O(1)，目标值在数组的第一个位置，只需要比较1次
// 最坏时间复杂度：O(n)，目标值在数组的最后位置或不存在，需要比较n次
// 平均时间复杂度：O(n)，目标值平均在数组的中间位置，平均比较次数=(1+2+...+n)/n=(n+1)/2

算法的空间复杂度

算法所需的存储空间

算法所需存储空间 = 程序本身所用的指令、常量、变量和输入数据的存储空间 + 算法执行过程中所需的额外辅助存储空间

  • 程序本身所用的指令、常量、变量和输入数据的存储空间：取决于问题本身，与算法无关。
  • 算法执行过程中所需的额外辅助存储空间：算法为完成数据处理逻辑，额外开辟的临时存储资源（如临时变量、递归调用栈、辅助数组等），其大小由所采用的算法决定。

此时，看一个算法所需的存储空间就只看算法执行过程中所需的额外辅助存储空间即可。

假设问题规模为n，算法执行过程中所需的额外辅助存储空间用f(n)表示，算法所需的存储空间用S(n)表示。则有S(n)=f(n)。

举个例子：

// 反转长度为n的数组
func reverseArray(arr []int, n int) []int {
    // 辅助数组：用于暂存反转后的结果
    temp := make([]int, n)       // 语句1：辅助空间大小为n
    
    // 将原数组逆序复制到辅助数组
    for i := 0; i < n; i++ {
        temp[n-1-i] = arr[i]
    }
    
    // 将辅助数组复制回原数组
    for i := 0; i < n; i++ {
        arr[i] = temp[i]
    }
    
    return arr
}

// S(n) = f(n) = n

算法的空间复杂度

算法的空间复杂度就是：算法执行所需的额外辅助存储空间关于问题规模n的函数f(n)的最高次项的数量级（Order），记作O(f(n))。

常见的空间复杂度

常见的空间复杂度：常数阶O(1)、线性阶O(n)、平方阶O(n²)
