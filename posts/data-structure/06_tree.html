（五）树与二叉树

树的定义

树（Tree）：是 n(n≥0) 个结点的有限集。

  • 若 n = 0，称为空树；
  • 若 n > 0，则它满足如下两个条件：
    1. 有且仅有一个特定的称为根的结点；
    2. 其余结点可分为 m (m≥0) 个互不相交的有限集 T1, T2, T3, …, Tm，其中每一个集合本身又是一棵树，并称为根的子树。

树的基本术语

  • 结点：树中的每个数据元素，包含数据项及指向子树的链接。
  • 结点的度：一个结点拥有的子树个数。
  • 树的度：树中所有结点的度的最大值。
  • 非终端结点：度不为 0 的结点。除根结点之外，非终端结点也称为内部结点。
  • 叶子结点：度为 0 的结点。
  • 双亲和孩子：结点的子树的根称为该结点的孩子；相应地，该结点称为孩子的双亲。
  • 兄弟：同一个双亲的孩子结点之间互称兄弟。
  • 堂兄弟：双亲在同一层次的结点之间互称堂兄弟。
  • 祖先：从根结点到该结点所经过的所有分支上的结点，包含该结点的双亲、双亲的双亲，直到根。
  • 子孙：以某结点为根的子树中的所有结点，包含该结点的孩子、孩子的孩子等所有后代。
  • 层次：从根结点开始定义，根为第 1 层，根的孩子为第 2 层，以此类推。
  • 树的深度：树中结点的最大层次。
  • 有序树：树中结点的各子树从左到右有次序关系，不可互换。
  • 无序树：树中结点的各子树没有次序，可以任意互换。
  • 森林：由 m（m≥0）棵互不相交的树组成的集合。

二叉树的定义

二叉树（Binary Tree）：是 n(n≥0) 个结点的有限集。

  • 若 n = 0，称为空树；
  • 若 n > 0，则它满足如下两个条件：
    1. 有且仅有一个特定的称为根的结点；
    2. 其余结点分为两个互不相交的子集 T1 和 T2，分别称为 T 的左子树和右子树，且 T1 和 T2 本身又都是二叉树。

二叉树与树的区别主要有以下两点：

  1. 二叉树的每个结点最多只有两个子树；而树的结点可以有任意多个子树。
  2. 二叉树的子树分为左子树和右子树，即使只有一棵子树也要区分左右；而当树的结点只有一棵子树时，就无须区分它是左还是右。

由上，

有 3 个结点的二叉树共有 5 种不同的形态。其中，最右侧的两种形态也称为斜树。

而有 3 个结点的树只有 2 种不同的形态。

二叉树的性质

  • 性质1：在二叉树的第 \(i\) 层上至多有 \(2^{i-1}\) 个结点 \((i ≥ 1)\)。
  • 性质2：深度为 \(k\) 的二叉树至多有 \(2^k - 1\) 个结点 \((k ≥ 1)\)。
  • 性质3：对任何一棵二叉树 \(T\)，如果其叶子数为 \(n_0\)，度为 2 的结点数为 \(n_2\)，则 \(n_0 = n_2 + 1\)。

满二叉树

满二叉树的定义

一棵深度为 \(k\) 且有 \(2^k - 1\) 个结点的二叉树称为满二叉树。

满二叉树的特点

  • 每层都满
  • 叶子结点全部在最底层

完全二叉树

完全二叉树的定义

深度为 \(k\) 的具有 \(n\) 个结点的二叉树，当且仅当其每一个结点都与深度为 \(k\) 的满二叉树中编号为 1~n 的结点一一对应时，称之为完全二叉树。

完全二叉树的特点

  • 前 \(k-1\) 层全满，最后一层左满右空。

完全二叉树的性质

  • 性质4：有 \(n\) 个结点的完全二叉树的深度为 \(\lfloor \log_2 n \rfloor + 1\)。
    （注：\(\lfloor x \rfloor\) 称作 \(x\) 的底，表示不大于 \(x\) 的最大整数）
  • 性质5：如果对一棵有 \(n\) 个结点的完全二叉树（其深度为 \(\lfloor \log_2 n \rfloor + 1\)）的结点按层序编号（从第 1 层到第 \(\lfloor \log_2 n \rfloor + 1\) 层，每层从左到右），则对任一结点 \(i\) \((1 ≤ i ≤ n)\)，有：
    1. 如果 \(i=1\)，则结点 \(i\) 是二叉树的根，无双亲；如果 \(i>1\)，则其双亲是结点 \(\lfloor i/2 \rfloor\)。
    2. 如果 \(2i > n\)，则结点 \(i\) 无左孩子（结点 \(i\) 为叶子结点）；否则其左孩子是结点 \(2i\)。
    3. 如果 \(2i + 1 > n\)，则结点 \(i\) 无右孩子；否则其右孩子是结点 \(2i + 1\)。

二叉树的顺序存储结构

二叉树的顺序存储就是通过把二叉树的结点按满二叉树进行编号，然后再依次放在数组对应的序号中进行存储。

二叉树的顺序存储最坏的情况就是：二叉树退化为一棵斜树时，此时树中仅有单侧连续结点有效，大量数组空间因无对应结点而被闲置空占，存储利用率极低。

由于二叉树的顺序存储结构比较浪费存储空间，因此仅适用于存储满二叉树和完全二叉树。

二叉树的遍历

假设：L：遍历左子树 D：访问根结点 R：遍历右子树。则遍历整个二叉树方案共有 DLR、LDR、LRD、DRL、RDL、RLD 六种。

若规定先左后右，按照根节点的访问顺序可分为三种情况：

  • DLR 先序遍历
  • LDR 中序遍历
  • LRD 后序遍历

二叉树的递归遍历

// 先序遍历
bool PreOrderTraverse(BiTree T, void (*visit)(BiTree)) {
    if(T==NULL) return true;
    else {
        visit(T);
        PreOrderTraverse(T->lchild, visit);
        PreOrderTraverse(T->rchild, visit);
    }
}

// 中序遍历
bool InOrderTraverse(BiTree T, void (*visit)(BiTree)) {
    if(T==NULL) return true;
    else {
        InOrderTraverse(T->lchild, visit);
        visit(T);
        InOrderTraverse(T->rchild, visit);
    }
}

// 后序遍历
bool PostOrderTraverse(BiTree T, void (*visit)(BiTree)) {
    if(T==NULL) return true;
    else {
        PostOrderTraverse(T->lchild, visit);
        PostOrderTraverse(T->rchild, visit);
        visit(T);
    }
}

int BiTreeDepth(BiTree T) {
    if (!T) return 0;
    int leftDepth = BiTreeDepth(T->lchild);
    int rightDepth = BiTreeDepth(T->rchild);
    return (leftDepth > rightDepth ? leftDepth : rightDepth) + 1;
}

    return true;
}

线索二叉树

遍历二叉树就是以一定规则将二叉树中的结点排列成一个线性序列，也就是各结点的排列从一棵树变成了一个线性表。

通过遍历之后得到的结点序列，我们可以很清楚的知道任意一个结点，它的前驱和后继是哪一个。但是，这是建立在遍历的基础上的，每次想要获得一个结点的前驱或后继，都必须重新遍历整棵树。所以这种方式效率比较低。

或者可以在每个结点中增加两个指针域来存放在遍历时得到的有关前驱和后继信息，但这样做使得结构的存储密度大大降低。

由于有 n 个结点的二叉链表中必定存在 n+1 个空指针域，因此可以充分利用这些空指针域来存放结点的前驱和后继信息。

利用二叉链表中的空指针域：

  • 如果某个结点的左指针为空，则将其指向其前驱结点。
  • 如果某个结点的右指针为空，则将其指向其后继结点。

这种改变指向的指针称为线索。

加上了线索的二叉树称为线索二叉树。

按照某种遍历顺序构建线索二叉树的过程叫做二叉树的线索化。

为区分lrchid和rchild指针到底是指向孩子的指针，还是指向前驱或后继的指针，对二叉链表中每个结点增设两个标志域 ltag 和 rtag，并约定：

  • ltag = 0，表示 lchild 指向该结点的左孩子。
  • ltag = 1，表示 lchild 指向该结点的前驱。
  • rtag = 0，表示 rchild 指向该结点的右孩子。
  • rtag = 1，表示 rchild 指向该结点的后继。
typedef struct BiThrNode {
    ElemType data;
    int ltag, rtag;
    struct BiThrNode *lchild, *rchild;
} BiThrNode, *BiThrTree;

中序线索化的二叉树

中序线索化的二叉树找结点的前驱：

  • ltag = 1 ：左指针指向的就是该结点的前驱。
  • ltag = 0 ：前驱为该结点左子树最右下的结点。
    （从左子树的根开始，沿着右子树不断向右，知道没有右子树的那个结点。）

中序线索化的二叉树找结点的后继：

  • rtag = 1 ：右指针指向的就是该结点的后继。
  • rtag = 0 ：后继为该结点右子树最左下的结点。
    （从右子树的根开始，沿着左子树不断向左，知道没有左子树的那个结点。）

使用中序线索化二叉树遍历整棵树就是从第一个结点开始不断找后继的过程。相比于未线索化的二叉树，直接省去了栈空间。

先序线索化的二叉树

先序线索化的二叉树找结点的前驱：

  • ltag = 1 ：左指针指向的就是该结点的前驱。
  • ltag = 0 ：
    • 如果该结点是整棵树的根结点，则无前驱。
    • 如果该结点是其父结点的左孩子，则前驱为该结点的父结点。
    • 如果该结点是其父结点的右孩子，并且该父结点没有左兄弟，则前驱为该父结点。
    • 如果该结点是其父结点的右孩子，并且该父结点有左兄弟，则前驱为该父结点的左子树先序遍历最后访问的结点。

由于先序线索化的二叉树无法直接找到其父结点，因此无法有效查找前驱。

先序线索化的二叉树找结点的后继：

  • rtag = 1 ：右指针指向的就是该结点的后继。
  • rtag = 0 ：
    • 如果该结点有左孩子，则后继为该结点的左孩子。
    • 如果该结点没有左孩子，则后继为该结点的右孩子（必有右孩子）。

与中序线索化二叉树一样，使用先序线索化二叉树遍历整棵树也是从第一个结点开始不断找后继的过程。也是直接省去了栈空间。

后序线索化的二叉树

后序线索化的二叉树找结点的前驱：

  • ltag = 1 ：左指针指向的就是该结点的前驱。
  • ltag = 0 ：
    • 如果该结点有右孩子，则前驱为该结点的右孩子。
    • 如果该结点没有右孩子，则前驱为该结点的左孩子（必有左孩子）。

后序线索化的二叉树找结点的后继：

  • rtag = 1 ：右指针指向的就是该结点的后继。
  • rtag = 0 ：
    • 如果该结点是整棵树的根结点，则无后继。
    • 如果该结点是其父结点的右孩子，则后继为该结点的父结点。
    • 如果该结点是其父结点的左孩子，并且该父结点没有右兄弟，则后继为该父结点。
    • 如果该结点是其父结点的左孩子，并且该父结点有右兄弟，则后继为该父结点的右子树后序遍历第一个访问的结点。

由于后序线索化的二叉树无法直接找到其父结点，因此无法有效查找后继。因此，如果使用后序线索化二叉树遍历整棵树，仍需要栈的支持。

哈夫曼树

  • 路径：从树中一个结点到另一个结点之间的分支构成这两个结点之间的路径。
  • 路径长度：路径上的分支数目称作路径长度。
  • 树的路径长度：从树的根结点到每一个结点的路径长度之和，记作 TL。
    • TL(a) = 0 + 1 + 1 + 2 + 2 + 3 + 3 + 4 + 4 = 20
    • TL(b) = 0 + 1 + 1 + 2 + 2 + 2 + 2 + 3 + 3 = 16

    结点数目相同的二叉树中，完全二叉树是路径长度最短的二叉树。

  • 权：给树中的边或结点赋予一个有着某种含义的数值，则这个数值称为该边或结点的权，也就是对应的边权或结点权。
  • 结点的带权路径长度：从根结点到该结点之间的路径长度与该结点的权的乘积。
  • 树的带权路径长度：树中所有叶子结点的带权路径长度之和，记作 \(WPL = \sum\limits_{k=1}^n w_k l_k\)。
    • WPL(a) = 7×2 + 5×2 + 2×2 + 4×2 = 36
    • WPL(b) = 7×3 + 5×3 + 2×1 + 4×2 = 46
  • 哈夫曼树：假设有 \(m\) 个权值 \({w_1, w_2,...,w_m}\)，可以构造一棵含 \(n\) 个叶子结点的二叉树，每个叶子结点的权为 \(w_i\)，则其中带权路径长度 \(WPL\) 最小的二叉树称做最优二叉树或哈夫曼树。

    • 哈夫曼树的特点：

    • 哈夫曼树中权越大的叶子结点离根结点越近。
    • 对于一组给定的权值，哈夫曼树的构造结果可能不唯一，但所有可能的哈夫曼树都具有相同的最小带权路径长度。

哈夫曼树的构造

构造哈夫曼树的哈夫曼算法：

  1. 根据给定的 \(n\) 个权值 \(\{w_1,w_2,...,w_n\}\) 构成 \(n\) 棵二叉树的集合 \(F = \{T_1,T_2,...,T_n\}\)，其中每棵二叉树 \(T_i\) 中只有一个带权为 \(w_i\) 的根结点，其左右子树均为空。
  2. 在 \(F\) 中选取两棵根结点的权值最小的树作为左右子树构造一棵新的二叉树，且置新的二叉树的根结点的权值为其左右子树上根结点的权值之和。
  3. 在 \(F\) 中删除这两棵树，同时将新得到的二叉树加入 \(F\) 中。
  4. 重复步骤 2 和 3 ，直到 \(F\) 只含一棵树为止。这棵树便是哈夫曼树。

哈夫曼算法的特点：

  • 在哈夫曼算法中，初始时有 \(n\) 棵二叉树，要经过 \(n-1\) 次合并最终形成哈夫曼树。
  • 经过 \(n-1\) 次合并产生 \(n-1\) 个新结点，且这 \(n-1\) 个新结点都是具有两个孩子的分支结点。

所以，哈夫曼树中共有 \(n+n-1 = 2n-1\) 个结点，且其所有的非终端结点的度均不为 1。

哈夫曼算法的代码实现

typedef struct {
    int weight;
    int parent, lch, rch;
} HTNode, *HuffmanTree;

// CreatHuffmanTree 构造哈夫曼树
void CreatHuffmanTree(HuffmanTree HT, int n) {
    // 若结点数 <= 1，不用构造哈夫曼树（至少需要两个叶子才能合并）
    if (n <= 1) return;
    // 哈夫曼树总结点数：n个叶子 + (n-1)个非叶子 = 2n-1
    m = 2 * n - 1;
    // 用动态数组存储哈夫曼树（顺序存储结构），下标 0 闲置，1~n 是初始叶子结点，n+1~m 是后续生成的非叶子结点。
    HT = new HTNode[m + 1];
    // 初始化所有结点，将其父结点、左子树、右子树均设为 0
    for (i = 1; i <= m; ++i) {
        HT[i].lch = 0;
        HT[i].rch = 0;
        HT[i].parent = 0;
    }
    // 手动输入数组前 n 个位置（1~n）存放初始的叶子结点的权值
    for (i = 1; i <= n; ++i)
        cin >> HT[i].weight;

    for (i = n + 1; i <= m; i++) {  // 生成n-1个非叶子结点（从n+1到m）
        Select(HT, i - 1, s1, s2);  // 选两个权值最小且无父结点的结点
        HT[s1].parent = i;        // 1. 将选中的两个结点的父结点设为i
        HT[s2].parent = i;
        HT[i].lch = s1;          // 2. 将i的左孩子设为s1，右孩子设为s2
        HT[i].rch = s2;
        HT[i].weight = HT[s1].weight + HT[s2].weight;   // 3. i的权值 = 两孩子权值之和
    }
}

// 辅助函数：Select 选择两个权值最小且无父结点的结点
void Select(HuffmanTree HT, int k, int &s1, int &s2) {
    // 1. 先找第一个最小的（s1）
    int min1 = 无穷大;
    for (int j = 1; j <= k; j++) {
        if (HT[j].parent == 0 && HT[j].weight < min1) {
            min1 = HT[j].weight;
            s1 = j;
        }
    }

    // 2. 再找第二个最小的（s2，且s2 != s1）
    int min2 = 无穷大;
    for (int j = 1; j <= k; j++) {
        if (HT[j].parent == 0 && HT[j].weight < min2 && j != s1) {
            min2 = HT[j].weight;
            s2 = j;
        }
    }
}

哈夫曼编码

在通信中，数据是以二进制比特流的形式进行传输的。因此，需要将发送的报文中的字符编码为二进制。

假设将字符与二进制数从小到大依次对应来编码，例如：

  • a —— 0
  • b —— 1
  • c —— 10
  • d —— 11

此时，假如发送的字符序列为 "abac"，则编码为 "01010" 。

那在译码时，上述编码就会出现歧义，因为 "010" 可能是 "ac" ，也可能是 "aba"。这就导致无法解码为原始的字符序列。

导致以上问题的原因就是：一个字符的编码是另一个字符的前缀。这就会导致出现歧义而无法解码。

为了解决这个问题，我们可以等长编码，例如：

  • a —— 00
  • b —— 01
  • c —— 10
  • d —— 11

这样就避免了前缀问题，对于字符序列 "abac"，则编码为 "00010010"。可以唯一地解码为 "abac"。

等长编码虽然避免了前缀问题，但是这种编码方案的编码长度比较长，并不是最优的编码方案。

那么在不出现歧义的情况下，能够实现最短编码的编码方案就是哈夫曼编码。

哈夫曼编码的思想：

  1. 统计字符集中每个字符在报文中出现的平均概率（出现概率越大的就编码的越短）。
  2. 利用哈夫曼树的特点：权值越大的叶子结点离根结点越近。将每个字符的概率值作为权值，构造哈夫曼树。这样就可以保证概率越大的结点，路径越短。
  3. 把哈夫曼树中的结点的左分支标为 0，右分支标为 1。把从根结点到每个叶子结点的路径上的所有分支连接起来，就是该叶子结点代表的字符的编码。

  1. 为什么哈夫曼编码能够保证是前缀编码?

    2. 因为没有一片树叶是另一片树叶的祖先，所以每个叶子结点的编码就不可能是其它叶子结点编码的前缀。

  2. 为什么哈夫曼编码能够保证字符编码总长最短?

    3. 因为哈夫曼树的带权路径长度最短，故字符编码的总长最短。

哈夫曼编码的代码实现

哈夫曼编码

/*
前提条件：调用此函数前必须已正确构建哈夫曼树HT，满足：
哈夫曼树的叶子结点编号固定为1 ~ n（n 是原始字符的个数）
所有非叶子结点编号为n+1 ~ 2n-1（哈夫曼树的总结点数 = 2n-1）
根结点的parent值必须为0
*/
void CreatHuffmanCode(HuffmanTree HT, HuffmanCode &HC, int n) {
    // 分配一个长度为n+1的指针数组，每个元素将指向一个字符的编码字符串（为什么是n+1而不是n？因为叶子结点编号从1开始，索引0闲置不用，方便编号和数组下标一一对应）
    HC = new char*[n + 1];
    // 分配一个临时字符数组，用于暂存当前正在生成的单个字符的编码（为什么长度是n？因为哈夫曼编码的最大可能长度是 n-1（最坏情况：哈夫曼树退化成一条链），加上字符串结束符'\0'，正好需要 n 个字符空间）
    char* cd = new char[n];
    // 先将临时数组的最后一位设为字符串结束符'\0'（从后往前填充编码内容，最后一位永远是结束符）
    cd[n - 1] = '\0';
    for (int i = 1; i <= n; ++i) {  // 循环 n 次，依次为编号1~n的每个叶子结点（对应每个原始字符）生成编码
        int start = n - 1;  // 临时数组cd的当前写入位置，初始化为结束符的前一位
        int c = i;          // 当前正在处理的结点编号，初始化为当前叶子结点 i
        int f = HT[i].parent;   // 当前结点的父结点编号，初始化为叶子结点 i 的父结点
        while (f != 0) {    // 循环终止条件是到达根结点（根结点的 parent=0）
            --start;        // 将写入位置向前移动一位（因为我们从后往前写编码）
            cd[start] = (HT[f].lchild == c) ? '0' : '1';  // 如果当前结点是父结点的左子树，则编码为0，否则为1
            c = f;  // 更新当前结点编号为父结点编号
            f = HT[f].parent;   // 将父结点更新为祖父结点，继续向上回溯
        }
        HC[i] = new char[n - start];    // 为当前字符的编码分配精确大小的内存空间（从start到n-1共有(n-1 - start + 1) = n - start个字符（包括结束符）），这保证了每个编码只占用刚好需要的内存，没有浪费
        strcpy(HC[i], &cd[start]);  // 将临时数组cd中从start位置开始的完整字符串，复制到编码表HC的第 i 个位置
    }
    delete[] cd;    // 释放临时内存
}

哈夫曼解码

void HuffmanDecode(HuffmanNode HT[], int n, char ch[], const char code[], char decoded[]) {
    int root = 2 * n - 1;        // 根结点下标（哈夫曼树共有2n-1个结点）
    int p = root;                // 当前遍历到的结点，从根开始
    int idx = 0;                 // 解码结果字符串的当前位置
    int len = strlen(code);      // 编码串长度

    for (int i = 0; i < len; ++i) {
        // 根据编码字符决定向左（0）还是向右（1）
        if (code[i] == '0')
            p = HT[p].lchild;
        else // '1'
            p = HT[p].rchild;

        // 如果当前结点是叶子结点（通常叶子结点的左右孩子均为0）
        if (HT[p].lchild == 0 && HT[p].rchild == 0) {
            // 输出该叶子结点对应的字符
            decoded[idx++] = ch[p];
            // 回到根结点，继续解码下一位
            p = root;
        }
    }
    decoded[idx] = '\0';  // 添加字符串结束符
}
