MySQL 笔记

数据库概述

数据库（Database，简称 DB）：按照数据结构来组织、存储和管理数据的仓库。

数据库管理系统（Database Management System，简称 DBMS）：操纵和管理数据库的大型软件。

SQL：结构化查询语言。

三者关系：DBMS 执行 SQL 操作 DB。

组织：运用数据结构，把数据合理地摆放好。建立表、定义字段、建立关联。

存储：将数据持久化地保存在计算机的硬盘上，不会因断电而丢失。

管理：提供工具和语言（SQL）对数据进行增、删、改、查操作。

结构化查询：数据库本身是结构化的，SQL 语句按照这些结构查询。

安装与配置

  1. 将压缩包解压到某个文件夹
  2. 配置环境变量（将 bin 目录加入 Path）
  3. 以管理员身份运行黑窗口，进入 bin 目录
  4. 执行命令：mysqld --initialize --console，记住生成的密码
  5. 安装 MySQL 服务：mysqld -install
  6. 启动 MySQL 服务：net start mysql
  7. 登录 MySQL：mysql -uroot -p，输入随机密码
  8. 修改密码：ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';

卸载 MySQL

  1. 停止服务：net stop mysql
  2. 删除服务：mysqld --remove mysql
  3. 删除 MySQL 目录

简单查询

-- 查询一个字段
SELECT 字段名 FROM 表名;

-- 查询多个字段
SELECT 字段名1, 字段名2 FROM 表名;

-- 查询所有字段（不推荐使用 *）
SELECT * FROM 表名;

数值类型字段可直接参与数学运算

-- 计算员工年薪
SELECT ename, sal*12 FROM emp;

列起别名

-- 使用 AS 起别名
SELECT ename, sal*12 AS yearsal FROM emp;

-- AS 可以省略
SELECT ename, sal*12 yearsal FROM emp;

-- 别名中有空格，需用引号括起来（建议使用单引号）
SELECT ename, sal*12 'year sal' FROM emp;

条件查询

SELECT 字段1, 字段2, ...
FROM 表名
WHERE 条件;

-- 常见条件：=, !=, <>, >, >=, <, <=
-- AND (&&), OR (||)
-- BETWEEN ... AND ...
-- IN / NOT IN
-- IS NULL / IS NOT NULL
-- LIKE（模糊查询）

示例

-- 查询工资等于 3000 的员工
SELECT empno, ename FROM emp WHERE sal = 3000;

-- 查询工资大于 3000 的员工
SELECT empno, ename FROM emp WHERE sal > 3000;

-- 查询工资在 3000 到 5000 之间的员工
SELECT ename, sal FROM emp WHERE sal >= 3000 AND sal <= 5000;

-- AND 和 OR 同时使用，AND 优先级高于 OR，可用括号调整
SELECT ename, deptno, sal FROM emp
WHERE sal < 1500 AND (deptno = 20 OR deptno = 30);

-- BETWEEN ... AND ...（左小右大）
SELECT ename, sal FROM emp WHERE sal BETWEEN 1600 AND 3000;

-- IN 枚举
SELECT ename, sal, job FROM emp WHERE job IN ('MANAGER', 'SALESMAN');

-- NOT IN（注意 NULL 值问题）
SELECT ename, comm FROM emp WHERE comm NOT IN (NULL, 300);  -- 结果为空

-- IS NULL / IS NOT NULL
SELECT ename, sal, comm FROM emp WHERE comm IS NULL;

-- LIKE 模糊查询（% 任意多个字符，_ 任意一个字符）
SELECT ename FROM emp WHERE ename LIKE 'S%';
SELECT ename FROM emp WHERE ename LIKE '%O%';
SELECT ename FROM emp WHERE ename LIKE '_A%';

-- 转义特殊字符（如 _ 或 %）
SELECT name FROM student WHERE name LIKE '%\_%';

按某个字段排序

SELECT 字段1, 字段2, ...
FROM 表名
ORDER BY 字段 ASC/DESC;

-- 默认为升序（ASC）
-- 指定降序：ORDER BY 字段 DESC
-- 多个字段排序：ORDER BY 字段1 ASC/DESC, 字段2 ASC/DESC ...
-- 按工资升序
SELECT ename, sal FROM emp ORDER BY sal;

-- 按工资降序
SELECT ename, sal FROM emp ORDER BY sal DESC;

-- 先按工资升序，再按姓名升序
SELECT ename, sal FROM emp ORDER BY sal ASC, ename ASC;

-- 按查询结果中字段的位置排序（不推荐）
SELECT ename, sal FROM emp ORDER BY 2;

多行处理函数（分组函数）

特点：多个输入对应一个输出。使用前需分组，未分组时默认整表为一组。

注意：所有多行处理函数自动忽略 NULL；不能直接用在 WHERE 子句中。

COUNT()   -- 计数
MAX()     -- 最大值
MIN()     -- 最小值
SUM()     -- 求和
AVG()     -- 平均值

-- 示例
SELECT COUNT(ename) AS empnum FROM emp;
SELECT MAX(sal) FROM emp;
SELECT MIN(sal) FROM emp;
SELECT SUM(sal) FROM emp;
SELECT AVG(sal) FROM emp;

-- 组合使用
SELECT COUNT(ename), MAX(sal), MIN(sal), SUM(sal), AVG(sal) FROM emp;

-- COUNT(*) 与 COUNT(字段) 的区别
-- COUNT(字段)：统计该字段不为 NULL 的记录数
-- COUNT(*)：统计所有记录数

分组查询

SELECT ...
FROM ...
WHERE ...
GROUP BY 字段1, 字段2, ...
HAVING ...

-- 注意：SELECT 中只能跟分组函数或参与分组的字段
SELECT job, AVG(sal) FROM emp GROUP BY job;
SELECT deptno, MAX(sal) FROM emp GROUP BY deptno;
SELECT deptno, job, AVG(sal) FROM emp GROUP BY deptno, job;

-- HAVING：对分组后的数据进行过滤
-- 建议优先使用 WHERE 过滤，实在不行再用 HAVING
SELECT deptno, AVG(sal) FROM emp WHERE deptno <> 20 GROUP BY deptno;
SELECT deptno, AVG(sal) FROM emp GROUP BY deptno HAVING AVG(sal) > 2000;

-- 组内排序：找出每组前两名
SELECT SUBSTRING_INDEX(GROUP_CONCAT(empno ORDER BY sal DESC), ',', 2)
FROM emp GROUP BY job;

DISTINCT 关键字

-- 去重
SELECT DISTINCT job FROM emp;

-- DISTINCT 必须放在所有字段最前方，表示联合去重
SELECT DISTINCT deptno, job FROM emp;

-- 统计工作种类数量
SELECT COUNT(DISTINCT job) FROM emp;

LIMIT 与分页

-- 完整用法：LIMIT startIndex, length
-- startIndex 从 0 开始
-- 缺省用法：LIMIT index 表示取前 index 个

-- 取工资排名前五
SELECT ename, sal FROM emp ORDER BY sal DESC LIMIT 5;

-- 取工资排名 3-5 名
SELECT ename, sal FROM emp ORDER BY sal DESC LIMIT 2, 3;

-- 分页公式：每页 pageSize 条，第 pageNo 页
-- LIMIT (pageNo - 1) * pageSize, pageSize

连接查询

从两张或更多张表中联合查询数据。

分类

  • 内连接：等值连接、非等值连接、自连接
  • 外连接：左连接、右连接、全连接

笛卡尔积现象：两张表连接查询不加限制时，结果条数为两张表记录条数的乘积。需添加条件筛选。

内连接

-- 等值连接
SELECT e.ename, d.dname
FROM emp e
INNER JOIN dept d ON e.deptno = d.deptno;

-- 非等值连接
SELECT e.ename, e.sal, s.grade
FROM emp e
JOIN salgrade s ON e.sal BETWEEN s.losal AND s.hisal;

-- 自连接
SELECT e.ename 员工名, l.ename 领导名
FROM emp e
JOIN emp l ON e.mgr = l.empno;

外连接

-- 左外连接（左表全部显示）
SELECT d.*, e.ename
FROM dept d
LEFT OUTER JOIN emp e ON d.deptno = e.deptno;

-- 右外连接（右表全部显示）
SELECT d.*, e.ename
FROM emp e
RIGHT OUTER JOIN dept d ON d.deptno = e.deptno;

-- 外连接自连接
SELECT e.ename 员工名, l.ename 领导名
FROM emp e
LEFT JOIN emp l ON e.mgr = l.empno;

多表连接

SELECT e.ename, d.dname, s.grade
FROM emp e
JOIN dept d ON e.deptno = d.deptno
JOIN salgrade s ON e.sal BETWEEN s.losal AND s.hisal;

子查询

SELECT 语句中嵌套 SELECT 语句。

WHERE 后的子查询

-- 查询工资高于平均工资的员工
SELECT ename, sal FROM emp WHERE sal > (SELECT AVG(sal) FROM emp);

FROM 后的子查询（派生表）

-- 查询部门平均工资对应的薪资等级
SELECT t.*, s.grade
FROM (SELECT deptno, AVG(sal) avgsal FROM emp GROUP BY deptno) t
JOIN salgrade s ON t.avgsal BETWEEN s.losal AND s.hisal;

SELECT 后的子查询（标量子查询）

SELECT e.ename, (SELECT d.dname FROM dept d WHERE e.deptno = d.deptno) AS dname
FROM emp e;

EXISTS / NOT EXISTS

-- 查询有订单的客户
SELECT * FROM t_customer c
WHERE EXISTS (SELECT * FROM t_order o WHERE o.customer_id = c.customer_id);

-- 查询没有订单的客户
SELECT * FROM t_customer c
WHERE NOT EXISTS (SELECT * FROM t_order o WHERE o.customer_id = c.customer_id);

子查询典型场景总结

位置返回要求典型用途是否别名
SELECT 后必须单值添加计算列、关联信息否
FROM 后多行多列（表）数据预处理、复杂聚合是
WHERE 后单值或多值条件过滤、存在性判断否

UNION / UNION ALL

-- UNION 合并查询结果，自动去重
SELECT ename, job FROM emp WHERE job = 'MANAGER'
UNION
SELECT ename, job FROM emp WHERE job = 'SALESMAN';

-- UNION ALL 不去重，效率更高
-- 要求：两个结果集列数相同，列数据类型相同

存储引擎事务支持锁粒度外键主要优势适用场景
InnoDB✅行级锁✅事务安全、高并发、崩溃恢复默认选择，OLTP

数据库设计三范式

第一范式（1NF）

任何一张表都应该有主键，并且每一个字段原子性不可再分。

反例：一个单元格里存储多个联系方式，如 "电话:13800138000, 邮箱:abc@example.com"

后果：查询困难且低效，数据更新/删除异常，数据完整性无法保证。

第二范式（2NF）

建立在第一范式基础之上，所有非主键字段完全依赖主键，不能产生部分依赖。

反例：订单明细表主键为 (订单ID, 产品ID)，但包含客户姓名字段。

后果：数据冗余、更新异常、插入异常、删除异常。

解决方案：拆分为订单表和订单明细表。

第三范式（3NF）

建立在第二范式基础之上，所有非主键字段直接依赖主键，不能产生传递依赖。

反例：员工表中包含部门编号和部门经理字段。

后果：数据冗余、更新异常、插入异常、删除异常。

表关系设计

  • 多对多：三张表，关系表两个外键
  • 一对多：两张表，多的表加外键
  • 一对一：外键唯一

索引

索引是一种用来提高检索效率的数据结构。如同书籍的目录。

优点

  • 极大提高查询速度
  • 提高连接查询的效率
  • 减少排序和分组的时间

缺点

  • 占用额外空间
  • 降低增、删、改的速度

适合使用索引的情况

  • 频繁作为查询条件的列（WHERE 子句）
  • 用于表连接的列（JOIN ... ON ...）
  • 需要排序的列（ORDER BY）
  • 需要分组统计的列（GROUP BY）
  • 高选择性的列
  • 用于覆盖查询的列

不适合使用索引的情况

  • 频繁进行写操作的列
  • 很少被用于查询的列
  • 低选择性的列
  • 数据量很小的表

索引失效的情况

  • 数据量太小
  • 索引列的选择性差
  • 类型不匹配
  • OR 条件使用不当（两边包含无索引列）
  • 函数操作索引列
  • 联合索引未遵循最左前缀原则
  • 范围查询右侧的列
  • 模糊查询以 % 开头

索引类型

  • 按数据结构：B+树索引、哈希索引、全文索引、R树索引
  • 按物理存储：聚簇索引、非聚簇索引
  • 按逻辑功能：普通索引、唯一索引、主键索引、联合索引

B+树

  • B+树的叶节点层包含所有元素，从小到大排列，节点间用指针连接成链表
  • 非叶节点是叶节点的索引，加速查询
  • 兼顾顺序查找和随机查找

哈希索引

  • 通过哈希函数将关键字映射到地址
  • 直接定址法（无冲突）、除留余数法（可能冲突）
  • 处理冲突：开放地址法（线性探测、平方探测）、拉链法

全文索引

  • 基于倒排索引（词元 → 文档列表）
  • 支持关键词查询、短语查询、模糊查询、相关性排序
  • 核心算法：TF-IDF、BM25
  • 适用于搜索引擎、电商搜索、文档管理等场景

聚簇索引 vs 非聚簇索引

对比项聚簇索引非聚簇索引
数据存储叶子节点直接存放完整数据行索引和数据分开存储
物理顺序表数据物理顺序与索引顺序一致表数据物理顺序与索引无关
数量限制一个表只能有一个一个表可以有多个
InnoDB 实现主键自动成为聚簇索引叶子节点存储主键值

回表与覆盖索引

  • 回表：使用非聚簇索引查询时，需要回到聚簇索引查找完整行。
  • 覆盖索引：索引包含查询所需的所有列，不需要回表。

深度分页

查询大页码时，数据库需要扫描并丢弃之前页码的所有内容，导致大量无用 I/O 和 CPU 开销。

解决方案：

  • 游标分页（记录上一页最后一条的位置）
  • 覆盖索引 + 子查询
  • 业务层限制最大分页深度

InnoDB 三层 B+树容量估算

  • 页大小：16KB
  • 主键类型：8 字节，指针大小：6 字节
  • 非叶子节点：每个节点约 1170 个分支
  • 叶子节点：每条记录约 1KB，每个叶子节点约 16 条记录
  • 总容量 ≈ 1170 × 1170 × 16 ≈ 2200 万条

事务

事务是一个不可分割的最小工作单元，包含一系列操作，要么全部成功，要么全部失败。

ACID 特性

  • 原子性（A）：事务中所有操作要么全部提交成功，要么全部失败回滚。
  • 一致性（C）：事务前后，数据库从一个合法一致状态转换到另一个合法一致状态。
  • 隔离性（I）：多个并发事务之间相互隔离，互不干扰。
  • 持久性（D）：事务提交后，结果永久保存在数据库中。

隔离级别

隔离级别脏读不可重复读幻读
读未提交（READ UNCOMMITTED）✅✅✅
读已提交（READ COMMITTED）❌✅✅
可重复读（REPEATABLE READ）❌❌✅（InnoDB 通过 MVCC 解决）
串行化（SERIALIZABLE）❌❌❌

现象说明

  • 脏读：读取到另一个事务未提交的数据。
  • 不可重复读：同一事务内多次读取同一数据行，结果不一致。
  • 幻读：前后两次相同查询条件得到的结果集不一致（变多或变少）。

日志

日志类型作用说明
错误日志记录启动、运行、停止时的错误信息默认开启
二进制日志（Binlog）数据恢复、主从复制默认开启，格式：STATEMENT / ROW / MIXED
查询日志记录所有客户端操作语句默认不开启
慢查询日志记录执行时间超过阈值的 SQL默认不开启
重做日志（Redo Log）实现事务持久性记录数据页物理修改
回滚日志（Undo Log）提供回滚和 MVCC逻辑日志
中继日志（Relay Log）主从复制中转站仅存在于从库

锁

  • 读锁（共享锁）：允许多个事务同时读取，阻止修改。
  • 写锁（排他锁）：允许持有锁的事务读写，阻止其他事务访问。

锁的分类

  • 按粒度：全局锁、表级锁、行级锁、页级锁
  • 按模式：共享锁（S 锁）、排他锁（X 锁）、意向锁
  • 按算法：间隙锁、临键锁、记录锁
  • 按思想：悲观锁（SELECT ... FOR UPDATE）、乐观锁（版本号机制）

死锁

死锁是两个或多个事务相互等待对方释放锁资源，导致所有事务无法继续执行的永久阻塞状态。

四个必要条件：互斥条件、占有且等待、不可剥夺、循环等待。

排查：SHOW ENGINE INNODB STATUS; 或查询 performance_schema.data_locks。

MVCC（多版本并发控制）

  • MVCC 通过保存数据的历史版本，实现并发读写不阻塞。
  • 核心组件：隐藏字段（DB_TRX_ID、DB_ROLL_PTR）、Undo Log（回滚日志）、Read View（读视图）
  • 在 READ COMMITTED 和 REPEATABLE READ 隔离级别下生效。
  • RC 级别下，每次查询都生成新的 Read View；RR 级别下，事务内第一次查询时生成 Read View，后续复用。
